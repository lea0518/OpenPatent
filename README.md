# PatentRAG-Agent

基于 RAG 与多智能体协作的专利文书自动撰写系统。用户上传参考专利与技术交底书，系统检索相关内容作为撰写范本，分层生成说明书、权利要求书与摘要，并通过 LLM 评估与自修正闭环提升文书质量。

## 项目来源

本项目基于开源项目 [OpenPatent](https://github.com/hengyue-dunhuang/OpenPatent)（作者 hengyue-dunhuang，MIT 协议）二次开发，原项目提供了 Gradio 界面、PDF 章节分割与向量检索的基础框架。本仓库在此之上重构了生成流程、新增了评估与自修正机制，详见下方「相对原项目的改进」。

## 核心设计

### 三路物理隔离的向量库

摘要、说明书、权利要求书三种文体差异显著——权利要求是法律句式，摘要高度浓缩，说明书详细铺陈。若混在一个库中检索，生成权利要求时可能召回说明书段落，导致文体串味。

因此按专利法定章节切分，建立三个独立的 FAISS 索引（`IndexFlatL2`，bge-m3 embedding，1024 维），生成某部分时只检索同类内容。

切分依据专利公开文本的章节标题（`摘要` / `权 利 要 求 书` / `说 明 书` / `说 明 书 附 图`），采用顺序定位避免正文中「如权利要求 1 所述」这类引用被误判为章节起点。

### 分层串联生成

说明书信息最完整，故先生成；权利要求与摘要以已生成的说明书为唯一事实依据：

```text
技术交底书 → 术语表抽取
          → 说明书（检索说明书库作范本）
          → 权利要求书（注入说明书，确保特征有支撑）
          → 摘要（注入说明书，据此浓缩）
```

这一顺序对应专利法第 26 条第 4 款——权利要求书应当以说明书为依据。若让模型自行决定顺序，可能先写权利要求，此时缺少说明书作依据，支撑关系无法保证。

### 术语一致性约束

术语漂移（同一技术对象在不同部分使用不同名称）在专利中不是文风问题而是法律有效性问题：保护范围由权利要求的字面文义界定，用词不一致会导致范围解释争议，也可能被认定缺乏说明书支撑。

系统采用三层机制：

1. **抽取**：从交底书抽取关键术语构建术语表（temperature=0，确定性抽取）
2. **约束**：术语表注入生成与重写的 prompt，要求逐字沿用；生成温度降至 0.2，减少同义词随机替换
3. **检测与修正**：由评估器识别残留漂移，驱动闭环重写

需要说明的是，prompt 层面是强指令约束而非解码层面的硬约束，模型仍可能违反——这正是需要下游检测与修正的原因。

### LLM-as-a-Judge 评估

评估采用**问题提取**范式：要求裁判模型逐条列出具体问题并计数，而非给出整体评分。评分范式在实测中分数漂移严重、区分度低且扣分依据不可解释；问题提取的每一条都可人工核对，计数可累加，且能直接驱动重写。

三类问题对应不同的法律后果与修正目标：

| 类别 | 定义 | 修正目标 |
| --- | --- | --- |
| `term_drift` | 同一对象多个名称 | 权利要求 + 摘要（统一到说明书写法） |
| `unsupported_claims` | 权利要求特征在说明书中无对应描述 | 仅权利要求（说明书是事实源，应收窄范围而非补写说明书） |
| `fabricated_terms` | 交底书与术语表均无的自造名称 | 三部分 |

两项偏差规避措施：

- **自我偏袒偏差**：裁判模型优先使用与生成模型不同厂商的模型（默认 SiliconFlow 的 Qwen2.5-72B-Instruct，生成用 DeepSeek）。若回退到同一模型，报告中会显式标注风险警告。
- **位置偏见**：成对比较时正反各问一次（A/B 与 B/A），两次结论一致才采纳，矛盾则判平局。

### 自修正闭环

评估问题数超过阈值时，按问题类型路由重写对应部分，而非整体重新生成——这样可节省 token，且未改动的部分不会引入新问题。重写顺序固定为说明书 → 权利要求书 → 摘要，先修事实源再让下游对齐。

三道护栏：

- **达标阈值**（`ISSUE_THRESHOLD = 2`）：达到基线水平即停，不为清零而做高风险重写
- **轮数上限**（`MAX_REWRITE_ROUNDS = 2`）：防止无限循环，控制 API 开销
- **快照回滚**：重写前保存快照，复评后若问题数上升则还原并终止。LLM 重写不保证单调改善——修正一类问题可能引入另一类，没有回滚就可能交付比初稿更差的结果。

## 快速开始

### 环境要求

- Python 3.10（部分依赖在更高版本无对应 wheel）
- 两个 API Key：
  - **DeepSeek** — 文本生成
  - **SiliconFlow** — embedding（`BAAI/bge-m3`）与评估裁判

### 安装

```bash
git clone https://github.com/lea0518/PatentRAG-Agent.git
cd PatentRAG-Agent

conda create -n patentrag python=3.10 -y
conda activate patentrag

# 用 lock 文件复现已验证的依赖组合
pip install -r requirements.lock.txt
```

### 配置

复制 `.env.example` 为 `.env` 并填入你的 Key：

```bash
cp .env.example .env
```

`.env` 已在 `.gitignore` 中，不会被提交。

### 运行

```bash
python src/web_ui.py
```

浏览器打开 Gradio 输出的本地地址。Windows 下可直接运行 `run.bat`（自动激活 conda 环境并清理 7860 端口占用）。

### 使用流程

仓库已内置一套可直接运行的示例数据：`dbs/` 是由 7 篇「基于大语言模型的 XX 系统」类专利构建的向量知识库，`docs/示例技术交底书.docx` 是一份可直接使用的交底书。填好 API Key 后无需自备数据即可跑通全流程。

1. **加载知识库** — 在「1. 选择参考专利」中点击「已有本地知识库，点击这里」直接加载 `dbs/`；若要换成自己的语料，上传专利 PDF 后点击「处理专利文件」重新构建
2. **上传技术文档** — 在「2. 上传技术文档」中上传 `docs/示例技术交底书.docx`，或替换为你自己的交底书
3. **生成专利文档** — 在「3. 生成专利文档」中选择 stage 档位后一键分层生成，或单独生成某一部分
4. **查看与导出** — 生成结果可在界面预览，导出为 `.docx`

界面操作截图见 [`pic/`](pic/)。

### stage 档位

同一套代码通过 `stage` 参数控制启用哪些机制，用于消融对比：

| stage | 启用内容 |
| --- | --- |
| 0 | 基线：无术语表，独立生成，temperature 0.5/0.6 |
| 1 | + 术语表约束，temperature 降至 0.2 |
| 2 | + 分层串联（权利要求与摘要依赖已生成的说明书） |
| 3 | + 评估与自修正闭环 |

## 项目结构

```text
src/
├── web_ui.py            Gradio 界面、生成编排、自修正闭环
├── llm_integration.py   术语表抽取、初稿生成、反馈重写
├── evaluator.py         裁判模型选择、问题提取、成对比较
├── vector_db.py         FAISS 索引构建与检索
└── pdf_processor.py     专利 PDF 按法定章节切分

dbs/                     内置示例向量库（三路隔离，各 7 篇专利）
├── abstract(.texts.json)
├── claims(.texts.json)
└── specification(.texts.json)

docs/示例技术交底书.docx   可直接使用的输入示例
```

每个向量库是一对文件：无后缀的是 FAISS 索引（仅含向量），`.texts.json` 是下标到原文的映射。两者必须配对——FAISS 只返回整数下标，缺少文本映射时检索会取不到原文，因此 `load_index` 在文本文件缺失时直接抛异常而非降级。

生成的专利文书输出到 `outputs/`，该目录不纳入版本控制。

## 相对原项目的改进

- **可运行性修复** — 解决 gradio / fastapi / starlette / huggingface_hub 依赖版本冲突，修复 Windows GBK 控制台编码崩溃与硬编码路径问题，提供 `requirements.lock.txt` 锁定可用环境
- **配置解耦** — LLM 接口配置抽离至环境变量，可一处切换模型厂商
- **三路隔离检索** — 按文体建立独立向量库，替代原先的混合检索
- **分层串联生成** — 建立三部分的依赖关系，替代原先各部分独立生成
- **术语一致性机制** — 新增术语表抽取与注入，降低生成温度
- **评估 Agent** — 新增基于问题提取范式的评估模块，含异厂商裁判与位置偏见消除
- **自修正闭环** — 新增按问题类型路由的重写机制与三道护栏
- **健壮性** — 向量库文本单独持久化并在缺失时快速失败（原实现会静默返回空内容，导致检索失效却不报错）；参考专利单文件容错，损坏文件跳过而非整批失败

## 已知局限

- 章节切分针对中国专利公开文本的排版格式，其他格式需调整 `PDFProcessor.SECTIONS`
- 检索粒度为整章节，说明书可作二级切分以提升精度
- Embedding 为逐条串行调用，批量化可显著加快知识库构建
- 术语约束在 prompt 层面实现，非解码层面的硬约束
- 裁判模型未做人工一致性检验（Kappa / Spearman）
